**前置依赖**：授权账户（各工具官方登录）；独立示例 Git 项目。**这是唯一需要用户提供资源的项。**

**实施步骤**：
1. 安装并登录目标官方工具，先核对固定版本/banner/二进制摘要；与锁定身份不符时保持拒绝并新增显式版本 profile。
2. Codex 分别用 API key 与 ChatGPT 账号跑完整任务；Claude、DeepSeek、MiMo、Kimi Node、MiniMax、Grok 分别完成只读、写入、权限批准/拒绝、取消和失败注入。Grok 同时覆盖 `xai.api_key` 与 `cached_token`。
3. 保存脱敏协议 fixture 与 `identity_readback`/usage 事件，确认未知账户字段保持空，工具消息和个人信息不进入错误或事件。
4. 用一个 Teams DAG 让至少两个厂商承担不同节点，主机测试通过、源 checkout 不变；事件与被测 revision 归档。

**验收**：错提供商/错模型/错 effort 在提交前失败；无静默 API 回退；两厂商共同任务通过独立验收；每项实测有版本、任务、产物、测试证据。

## H04：预算真正约束原生消费（依赖 H03）

**现状**：整数微美元账本、原生 usage 观察归档、Automatic 决策估算的 1.25 安全系数预留、attempt 终态保守结算、运行收尾/重跑前对账均已接入。服务重启会在同一事务关闭当前中断团队的 hold，并在启动时扫描历史 Interrupted 团队的残留 hold；所有渠道仍为 `hard_budget_capable=false`，故 `budget_usd` 继续阻塞。工具自报金额保持未确认，不能作为账单。

**实施步骤**：
1. 接入至少一个提供商确认账单或额度来源，并把规划、执行、评审、重试、缓存和在途请求的确认金额归到 attempt；估算和确认值继续分字段。
2. 将确认金额传给 `settle_reservation(Some(actual))`，并证明在并发、取消、崩溃与重复启动时不会重复结算或漏结算。
3. 为支持的官方工具证明可验证的输出/轮数限制、提前停止和在途超额策略；没有这种证据的渠道保持不支持硬预算，UI 仅显示软预警。

**验收**：并发/崩溃不重复预留不漏结算；无零价未知项；最坏在途消耗可解释；只有能证明兑现的限制才解除 `budget_usd` 阻塞。
