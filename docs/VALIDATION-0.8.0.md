## Kimi 官方 CLI 实测

在主仓库外建立独立 JavaScript 工程，最初 4 项测试中 3 项失败。安装官方 `kimi-cli==1.50.0` 到独立 Python 环境并使用原生账号登录，经 Wonderland 的 Wire 适配器运行 `kimi-for-coding`。

1. 官方 ReadFile 读取源码/测试，WriteFile 提出 `totals.js` 补丁。
2. Wonderland 保存写入授权请求，确认后原工具完成修改。
3. 首轮因手动检查超过 300 秒，正确记录 timed_out，未声称成功。文件修改仍保留，供检查。
4. 新任务复查现有文件，经单次 Shell 授权运行 `node --test`，官方 ToolResult 报告 **4 passed / 0 failed**。
5. 在模型外再次执行 `npm test`，同样 **4 passed / 0 failed**；测试文件未改。
6. 任务结束进入 verifying，写入独立检查依据后才转 succeeded。
7. 实测发现 Wire 使用 `ContentPart` 封装文本/推理；补齐解析后重新调用只读 Chat，收到并持久化非空正文。

这验证的是单个官方执行器的真实工作闭环，不是自动跨模型调度成功，也不是与官方工具同等效率的对照实验。
