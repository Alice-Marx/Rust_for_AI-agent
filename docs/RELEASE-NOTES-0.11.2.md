# Wonderland 0.11.2 发布说明

## 桌面客户端一键更新

桌面端“应用”页新增“Wonderland 客户端”卡片，提供以下操作：

1. 点击“检查更新”，只检查 GitHub 的 stable Release；草稿和预发布版本不会进入自动更新流程。
2. 有新版本时点击“下载更新”。客户端只接受固定仓库、固定安装器文件名及随 Release 发布的 `SHA256SUMS.txt`，下载完成后核对文件长度和 SHA-256。
3. 校验通过后点击“安装并重启”。程序等待当前桌面窗口退出，再以原安装目录启动覆盖安装，并重新启动 Wonderland。

该流程不会改写已配置的数据目录，因此工作流、Teams 记录、登录配置和其他本地数据会保持在原数据目录。下载文件暂存于数据目录的 `updates` 文件夹；该目录不可用时会停止下载，不会改用系统临时目录。安装失败时会保留安装器和日志，便于定位问题。

SHA-256 核对用于确认下载文件与同一 GitHub Release 中的 `SHA256SUMS.txt` 一致。当前 Windows 安装器没有 Authenticode 签名，因此该核对不能代替独立代码签名或发布账号安全验证。

一键更新面向完整 Windows 安装版。便携 ZIP、缺少完整安装目录的副本或非 Windows 环境，请从 GitHub Release 手动安装对应版本。

## 覆盖安装与安装位置

`Wonderland-Setup-0.11.2-x64.exe` 支持选择安装目录和数据目录。升级现有安装时，选择原来的安装目录即可覆盖客户端程序；数据目录与安装目录独立，安装和卸载均不会自动删除其中的数据。

如希望完全避开 C 盘，可在安装向导中把安装目录和数据目录都选到其他磁盘。升级前无需为了更新手动移动数据目录；若要迁移数据目录，请先备份原目录，再在新目录完成启动和数据核对。

## 官方工具一键安装

桌面“应用”页为支持的官方工具显示“一键安装”按钮和对应安装命令。安装命令固定在客户端注册表中，界面不会接受任意命令输入；完成后会重新探测已安装的版本。安装过程展示进行状态、失败原因和受限的最近输出，失败后可重试。

该功能用于补齐受管执行器所需的官方 CLI。工具自身的登录、套餐、网络和厂商规则仍由对应厂商管理；安装成功不等同于账号已经登录或模型已经可用。

## Teams 跨厂商分工

Teams 的“逐节点指定模型”策略可以让不同节点使用不同厂商的官方执行器。每个节点在独立工作区执行，并声明可写路径；全部节点完成后，系统在 integration 工作区合并结果并运行团队级验收命令。

典型用法是：先在“应用”页安装并检测需要的官方工具，再在 Teams 中指定规划器和每个节点的执行器，启动团队后按界面提示处理权限请求，最后在团队详情与 `数据目录\\team-workspaces\\<team id>\\integration` 核对合并产物。Kimi × DeepSeek 的实际验证过程见 [跨厂商分工实验记录](EXPERIMENT-2026-09-24-CROSS-VENDOR-TEAM.md)。

## 同版本交付物

- `Wonderland-Setup-0.11.2-x64.exe`：Windows 安装器。
- `Wonderland-0.11.2-windows-x64.zip`：便携 ZIP。
- `rust-ai-wonderland-cli-0.11.2.tgz`：npm CLI 包。
- `SHA256SUMS.txt`：上述交付物的 SHA-256 清单。

## 仍需的验证记录

- Windows 覆盖安装：原安装目录不变、数据目录不变、桌面可重新启动。
- 桌面一键更新：检查、下载、摘要校验、安装器交接和失败日志提示。
- 用户真实账号：官方工具登录、工具探测和 Teams 分工执行。

详细工程变更、跨厂商实验和待办项见 [一键安装与实验工作报告](WORK-REPORT-2026-09-24-INSTALL-AND-EXPERIMENT.md)。
